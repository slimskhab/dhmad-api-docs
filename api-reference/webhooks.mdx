---
title: Webhooks API
description: Manage webhooks for real-time event notifications
---

The Webhooks API allows you to create and manage webhooks that receive real-time notifications when escrow status changes, contracts are signed, cancellation requests are created, accepted, or rejected, a buyer rejects delivery, funds are added or refunded on an escrow, a dispute on your sales opens or changes, or identity verification status changes.

<Warning>
  You can create a maximum of 2 webhooks per developer account. Choose your
  endpoints carefully.
</Warning>

<Note>
  On the live API, adding a webhook, changing its URL and regenerating its secret
  need a fresh confirmation by the DHMAD account that owns your developer
  account: its dhmad.tn passkey (Face ID, fingerprint or device PIN) when it has
  one, otherwise a 6-digit code sent to its email, or the code from its
  authenticator app when that is on. The [developer portal](https://developer.dhmad.tn/dashboard/webhooks) asks
  for it. Once a change is confirmed, the same portal session is not asked again
  for 2 hours while it keeps working. Changing only `events` or `isActive` does
  not need it, and the sandbox never does. See [Confirming a change](#confirming-a-change).
</Note>

## Create Webhook

Create a new webhook endpoint to receive event notifications.

<Endpoint method="POST" path="/api/developer/webhooks" />

### Request Body

<ParamField body="url" type="string" required>
  Webhook URL (must be HTTPS in production)
</ParamField>

<ParamField body="events" type="array">
  Array of event types to subscribe to. Supported: `escrow.status.updated`,
  `charge.status.updated` ([charges](/api-reference/charges/overview) — credit
  from `merchantReference`), `charge.funds.released`, `charge.dispute.opened`,
  `charge.refunded` and `charge.refund.updated` (charge refunds),
  `charge.chargeback.opened` and `charge.chargeback.resolved` (PayPal / card
  chargebacks on payments you created through the API),
  `dispute.opened`, `dispute.message.created` and `dispute.updated` (every
  dispute on your sales, from the [Disputes API](/api-reference/disputes/overview);
  `POST /api/v1/webhooks` with an API key needs the key's
  [Disputes access](/guides/api-keys#permissions) to subscribe to them, this
  endpoint does not),
  `contract.signed`, `escrow.cancellation.requested`,
  `escrow.cancellation.rejected`, `escrow.cancellation.accepted`,
  `escrow.updated`, `escrow.deposit_proof.rejected` (guest-checkout
  payment proof rejected by admin), `escrow.delivery.rejected` (buyer rejected
  delivery; includes optional reason), `escrow.funds.added`,
  `escrow.funds.refunded` (buyer add-funds / seller refund-funds adjustments),
  `escrow.funds.partially_released` (the buyer released part of a fixed-price
  escrow early; the escrow stays open), `escrow.release_request.created`, `escrow.release_request.approved`,
  `escrow.release_request.auto_approved`, `escrow.release_request.disputed`,
  `escrow.release_request.resolved`, `escrow.release_request.released`
  (per-period payouts on [progressive-release](/guides/progressive-release)
  escrows), `escrow.balance.exhausted` (no unreserved balance left; the escrow
  stays open for a top-up), `identity.verification.updated`
  (pre-account KYC approved or rejected), `identity.verification.linked`
  (KYC attached when user registers on DHMAD). Default: `["escrow.status.updated"]`
</ParamField>

### Example Request

<CodeGroup>
```bash cURL
curl -X POST https://dhmad.tn/api/developer/webhooks \
  -H "Authorization: Bearer your_developer_token" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://example.com/webhooks/dhmad",
    "events": ["escrow.status.updated"]
  }'
```

```javascript JavaScript
const response = await fetch("https://dhmad.tn/api/developer/webhooks", {
  method: "POST",
  headers: {
    Authorization: "Bearer your_developer_token",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    url: "https://example.com/webhooks/dhmad",
    events: ["escrow.status.updated", "contract.signed"],
  }),
});

const data = await response.json();
```

```python Python
import requests

headers = {
    'Authorization': 'Bearer your_developer_token',
    'Content-Type': 'application/json'
}

data = {
    'url': 'https://example.com/webhooks/dhmad',
    'events': ['escrow.status.updated', 'contract.signed']
}

response = requests.post(
    'https://dhmad.tn/api/developer/webhooks',
    json=data,
    headers=headers
)

data = response.json()
```

</CodeGroup>

### Example Response

```json
{
  "message": "Webhook created successfully",
  "webhook": {
    "id": "507f1f77bcf86cd799439011",
    "url": "https://example.com/webhooks/dhmad",
    "secret": "a1b2c3d4e5f6...your_webhook_secret_hex",
    "events": ["escrow.status.updated", "contract.signed"],
    "isActive": true,
    "createdAt": "2024-01-15T10:00:00Z"
  }
}
```

<Warning>
  The `secret` field is **only returned when creating a webhook** and when regenerating the secret. It is never included in list or get responses. Copy and store it immediately.
</Warning>

## Update Webhook

Update a webhook's URL, events, or active status.

<Endpoint method="PUT" path="/api/developer/webhooks/:id" />

### Path Parameters

<ParamField path="id" type="string" required>
  The webhook ID
</ParamField>

### Request Body

<ParamField body="url" type="string">
  New webhook URL (optional)
</ParamField>

<ParamField body="events" type="array">
  New array of event types (optional)
</ParamField>

<ParamField body="isActive" type="boolean">
  Whether the webhook is active (optional)
</ParamField>

### Example Request

```bash
curl -X PUT https://dhmad.tn/api/developer/webhooks/507f1f77bcf86cd799439011 \
  -H "Authorization: Bearer your_developer_token" \
  -H "Content-Type: application/json" \
  -d '{
    "isActive": false
  }'
```

## Regenerate Secret

Generate a new signing secret for a webhook. The old secret will immediately stop working.

<Endpoint method="POST" path="/api/developer/webhooks/:id/regenerate-secret" />

### Path Parameters

<ParamField path="id" type="string" required>
  The webhook ID
</ParamField>

### Example Request

```bash
curl -X POST https://dhmad.tn/api/developer/webhooks/507f1f77bcf86cd799439011/regenerate-secret \
  -H "Authorization: Bearer your_developer_token"
```

### Example Response

```json
{
  "message": "Webhook secret regenerated successfully",
  "secret": "e7f8a9b0c1d2...new_webhook_secret_hex"
}
```

<Warning>
  The new secret is only shown in this response. Copy and store it immediately, then update your webhook handler to use the new secret for signature verification.
</Warning>

## Confirming a change

Live only. Before `POST /api/developer/webhooks`, a `PUT` that sets a new `url`,
or `POST .../regenerate-secret`, start the check for that exact change:

```bash
curl -X POST https://dhmad.tn/api/developer/step-up/request \
  -H "Authorization: Bearer your_developer_token" \
  -H "Content-Type: application/json" \
  -d '{ "operation": "webhook_url", "resourceId": "507f1f77bcf86cd799439011", "url": "https://example.com/webhooks/new" }'
```

`operation` is `webhook_create` (with `url`), `webhook_url` (with `resourceId` and
the new `url`) or `webhook_secret` (with `resourceId`). When the owning account
has a dhmad.tn passkey, the answer is `"method": "passkey"` with
`passkeyOptions` (WebAuthn request options for the browser) and no code is sent;
add `"method": "code"` to the request to get a code instead. Otherwise the
answer carries `challengeId`, `challengeToken` and `method` (`email` or `totp`), or
`"required": false` when no check applies: the sandbox, an edit that keeps the
`url`, or a developer session that confirmed a change in the last 2 hours (the
answer then also carries `windowEndsAt`); send the change without the step-up
fields. Otherwise send the change itself with `stepUpChallengeId`,
`stepUpChallengeToken` and `stepUpCode` (the code from the email or the
authenticator app) in its body, or, after a passkey check, the browser's
WebAuthn answer as `stepUpPasskey`. A code or passkey answer confirms only the
change it was asked for and works once; asking again after 60 seconds sends a
new code. Passkeys are checked in the developer portal itself (they only work
on its address). After a confirmed code or passkey, the same session (the one your developer token belongs to, kept across
token refreshes) needs no new code for 2 hours after its last confirmed change,
and never more than 8 hours after the code; another session or a new sign-in
needs its own.

```json
{
  "url": "https://example.com/webhooks/new",
  "stepUpChallengeId": "6560c1f2a4b3c2d1e0f9a8b7",
  "stepUpChallengeToken": "f3a9…",
  "stepUpCode": "482913"
}
```

## Error Responses

### 400 Bad Request

**Webhook Limit Reached**

```json
{
  "error": "Maximum 2 webhooks allowed per developer"
}
```

**Invalid URL**

```json
{
  "error": "Invalid URL format"
}
```

**HTTPS Required (Production)**

```json
{
  "error": "Only HTTPS URLs are allowed in production"
}
```

### 403 Forbidden

**Confirmation needed** (live: the change was sent without a check)

```json
{
  "code": "DEVELOPER_STEP_UP_REQUIRED",
  "message": "Confirm this change with the code we send you."
}
```

**Wrong or used code** (`ACTION_STEP_UP_LOCKED` after 5 wrong codes: ask for a new one)

```json
{
  "code": "ACTION_STEP_UP_INVALID",
  "message": "Invalid verification code."
}
```

### 401 Unauthorized

```json
{
  "error": "Unauthorized",
  "message": "Invalid or missing developer token"
}
```

### 404 Not Found

```json
{
  "error": "Webhook not found"
}
```
